# 1. Общая концепция проекта

## 1.1. Назначение

MintTorrent — автономное серверное приложение, объединяющее полноценный BitTorrent-клиент qBittorrent и VPN-транспорт AmneziaWG в единую программную систему.

Главная особенность проекта — передача всего торрент-трафика через собственный userspace TCP/IP stack без использования системных VPN-интерфейсов.

Приложение должно позволять пользователю импортировать VPN-конфигурацию AmneziaWG, подключиться к VPN-серверу и использовать торрент-клиент через установленное соединение.

Пользователь должен иметь возможность управлять торрентами через оригинальный WebUI qBittorrent.

## 1.2. Основная философия

MintTorrent должен быть максимально автономным.

Для работы приложения не должно требоваться:
- Создание TUN/TAP-интерфейсов.
- Создание сетевых namespaces.
- Изменение системных маршрутов.
- Изменение DNS-конфигурации Linux.
- Настройка iptables.
- Настройка nftables.
- Установка системного VPN-клиента.
- Ручная настройка сетевой подсистемы ОС.

Приложение должно самостоятельно управлять VPN, внутренней маршрутизацией и торрент-трафиком.

## 1.3. Основные цели

1. Объединение VPN и BitTorrent в одном приложении.
2. Полностью userspace-архитектура.
3. Использование Rust в качестве основного языка.
4. Сохранение оригинального qBittorrent WebUI.
5. Прямая интеграция торрент-движка с внутренним сетевым стеком.
6. Полноценная поддержка IPv4 и IPv6.
7. Защита от утечек трафика.
8. Автоматическое восстановление VPN.
9. Автономная установка и эксплуатация.
10. Поддержка systemd.

# 5. AmneziaWG Transport

## 5.1. Назначение

Модуль отвечает за VPN-соединение между MintTorrent и удалённым VPN endpoint.

## 5.2. Требования

- Импорт конфигураций AmneziaWG.
- Проверка корректности конфигураций.
- Поддержка приватных и публичных ключей.
- Поддержка endpoint.
- Поддержка AllowedIPs.
- Поддержка специфических параметров AmneziaWG.
- Передача зашифрованных UDP-пакетов.
- Приём входящих UDP-пакетов.
- Мониторинг handshake.
- Автоматическое переподключение.
- Корректное завершение соединения.

## 5.3. Интеграция

VPN-транспорт должен взаимодействовать с внутренним сетевым стеком через программный интерфейс передачи IP-пакетов.

Запрещено использовать системный TUN-интерфейс.

Предпочтительный вариант — адаптация интерфейса `tun.Device` AmneziaWG-Go для работы с внутренним userspace stack.

Допускается:
- Использование существующей Rust-реализации AmneziaWG.
- FFI с AmneziaWG-Go.
- Отдельный внутренний VPN-компонент.

Обязательное условие — сохранение совместимости с протоколом AmneziaWG.

Обычный WireGuard не должен использоваться вместо AmneziaWG без явного согласования.

# 6. Userspace Network Stack

## 6.1. Назначение

Собственный сетевой стек является основой архитектуры MintTorrent.

Он обеспечивает внутреннюю сетевую среду, через которую торрент-движок взаимодействует с внешней сетью.

## 6.2. Требования

Обязательно:
- IPv4.
- IPv6.
- TCP.
- UDP.
- DNS.
- Обработка IP-пакетов.
- Маршрутизация внутри userspace.
- Поддержка входящих соединений.
- Поддержка исходящих соединений.
- Управление сокетами.
- Обработка сетевых ошибок.
- Тайм-ауты.
- Асинхронная обработка операций.

## 6.3. Выбор реализации

Исследовать три варианта.

**Вариант A — gVisor Netstack**

Использование готового userspace TCP/IP stack с адаптацией к Rust через FFI или другой внутренний интерфейс.

**Вариант B — smoltcp**

Использование Rust-совместимого сетевого стека.

Необходимо отдельно проверить возможность построения полноценного TCP/UDP backend для libtorrent, а не ограничиваться поддержкой базового IP.

**Вариант C — альтернативный userspace stack**

Допускается выбор другого решения при условии:
- Поддержки IPv4 и IPv6.
- Поддержки TCP и UDP.
- Возможности интеграции с libtorrent.
- Возможности передачи пакетов непосредственно в AmneziaWG.

Окончательный выбор должен быть обоснован сравнительными тестами.

# 7. Прямая интеграция с libtorrent

## 7.1. Основное требование

Использование SOCKS5, HTTP CONNECT и других прокси полностью запрещено.

Торрент-движок должен напрямую использовать внутренний сетевой backend MintTorrent.

## 7.2. Сетевой backend

Необходимо разработать собственный backend для libtorrent.

Он должен обеспечивать:
- Исходящие TCP-соединения.
- Входящие TCP-соединения.
- UDP-соединения.
- UDP datagram transmission.
- UDP reception.
- DNS resolution.
- IPv4.
- IPv6.
- Управление портами.
- Тайм-ауты.
- Асинхронную обработку.
- Корректное закрытие соединений.

## 7.3. Интеграция

Изучить архитектуру сетевого слоя используемой версии libtorrent.

Предпочтительно использовать существующие точки расширения socket_type и связанные механизмы.

Если API libtorrent не позволяет полностью заменить системный сетевой backend, допускается:
- Модификация исходного кода libtorrent.
- Создание собственного backend на основе исходников libtorrent.
- FFI между Rust и C++.
- Создание отдельного совместимого сетевого слоя.

Изменения libtorrent должны быть минимальными и документированными.

## 7.4. Требования к системным сокетам

Торрент-движок не должен использовать обычные системные TCP/UDP-сокеты для внешних P2P-соединений.

Все сетевые операции торрент-движка должны проходить через внутренний backend.

Исключение — служебные соединения, необходимые для управления приложением и WebUI.

Системная таблица маршрутизации Linux не должна изменяться.

# 12. Защита и отказоустойчивость

## 12.1. Fail-Closed

MintTorrent должен реализовывать принцип Fail-Closed.

При потере VPN:
- Все торрент-соединения прекращают передачу.
- Новые P2P-соединения блокируются.
- Внутренний сетевой backend переходит в безопасное состояние.
- DNS-запросы торрент-движка блокируются.
- Автоматически начинается процедура восстановления VPN.

Запрещено переключение на системное подключение.

## 12.2. Контроль состояния

Мониторинг должен проверять:
- Состояние VPN.
- Handshake.
- Доступность VPN endpoint.
- Доступность внешней сети через VPN.
- Работу внутреннего TCP/IP stack.
- Состояние торрент-движка.

Наличие handshake само по себе не должно считаться достаточным доказательством работоспособности VPN.

## 12.3. Восстановление

При потере соединения:
1. Заблокировать новый внешний торрент-трафик.
2. Завершить или приостановить неработающие сетевые операции.
3. Попытаться восстановить VPN.
4. Проверить реальную передачу данных через туннель.
5. Восстановить работу сетевого backend.
6. Возобновить торрент-операции.

Предусмотреть экспоненциальную задержку повторных попыток.

Формат конфигурации — TOML.

Пример:

```toml

stack = "auto"

[network.ipv4]
enabled = true

[network.ipv6]
```

## 18.3. Поддержка systemd

MintTorrent должен поддерживать полноценную интеграцию с systemd.

Необходимо предоставить готовый unit-файл:

`minttorrent.service`

Пример:

```ini
[Unit]
Description=MintTorrent - Userspace VPN BitTorrent Server
Documentation=https://github.com/PROJECT/MintTorrent
After=network-online.target
Wants=network-online.target

[Service]
Type=exec

User=minttorrent
Group=minttorrent

WorkingDirectory=/opt/MintTorrent

ExecStart=/opt/MintTorrent/bin/minttorrent run --foreground

Restart=on-failure
RestartSec=5

KillSignal=SIGTERM
TimeoutStopSec=60

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

ReadWritePaths=/var/lib/minttorrent
ReadWritePaths=/var/log/minttorrent
ReadWritePaths=/etc/minttorrent

[Install]
WantedBy=multi-user.target
```

Unit-файл является предварительным шаблоном. Параметры sandboxing должны проверяться на совместимость с выбранными библиотеками и механизмами VPN-транспорта.

# 22. Итоговая архитектурная концепция

MintTorrent — не VPN-прокси, не оболочка над системным VPN-клиентом и не самостоятельная замена qBittorrent.

Это автономная серверная платформа, объединяющая:

- Rust Application Core.
- AmneziaWG Transport.
- Userspace TCP/IP Stack.
- Собственный сетевой backend libtorrent.
- Оригинальный qBittorrent WebUI.
- Интеграцию с systemd.

Основное архитектурное требование:

**Торрент-движок должен работать исключительно через внутренний userspace transport MintTorrent. Он не должен использовать системную сетевую подсистему для внешних P2P-соединений.**

Административный интерфейс при этом должен оставаться доступным независимо от состояния VPN.

## Конечный пользовательский сценарий

1. Пользователь скачивает MintTorrent.
2. Распаковывает Standalone Bundle.
3. Запускает `install.sh`.
4. Приложение устанавливается в `/opt/MintTorrent`.
5. Создаётся отдельный пользователь `minttorrent`.
6. Устанавливается systemd unit.
7. Пользователь импортирует конфигурацию AmneziaWG.
8. Указывает каталог загрузок.
9. Запускает сервис через systemd.
10. MintTorrent самостоятельно поднимает VPN.
11. Запускается торрент-движок.
12. Пользователь открывает оригинальный qBittorrent WebUI.
13. Управляет загрузками и раздачами.

Вся торрент-сетевая активность проходит через внутренний VPN-транспорт.

**Главная цель MintTorrent — предоставить полноценный автономный BitTorrent-сервер с оригинальным qBittorrent WebUI и встроенным AmneziaWG, не требующий системных VPN-интерфейсов, изменения сетевой конфигурации Linux и установки пакетов через системный пакетный менеджер.**
